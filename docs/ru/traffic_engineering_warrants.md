# 🚦 Светофорные обоснования организации движения и анализ инфраструктуры

Данный документ описывает подсистему инженерного анализа обоснований установки светофоров CARINA, расположенную в каталоге [`src/analysis/`](../../src/analysis). В нем подробно рассматриваются математические формулировки и автоматизированная оценка нормативных критериев введения светофорного регулирования на основе стандарта **FHWA MUTCD** (Manual on Uniform Traffic Control Devices) и муниципальных нормативов.

## 1. Автоматизированная оценка обоснований светофорного регулирования

Перед установкой новых светофорных объектов или изменением режимов работы инженеры организации дорожного движения обязаны нормативно доказать выполнение инженерных критериев (warrants). **Интеллектуальная система анализа (Smart Analysis System — SAS)** агрегирует исторические данные из PostgreSQL для определения целесообразности светофорного регулирования или корректировки пофазного разъезда.

```text
 Исторические данные трафика (PostgreSQL `synapse_fluid_dynamics`)
                             │
                             ▼
                ┌─────────────────────────┐
                │ InfrastructureAnalyzer  │
                └────────────┬────────────┘
                             │
              ┌──────────────┴──────────────┐
              ▼                             ▼
   ┌──────────────────────┐      ┌──────────────────────┐
   │   WarrantEvaluator   │      │     WarrantMath      │
   │(Стратегии критериев) │      │(Расчет потоков/скор.)│
   └──────────┬───────────┘      └──────────────────────┘
              │
              ├──> Критерий 1: VolumeWarrant (Интенсивности Таблицы MUTCD 4C-1)
              ├──> Критерий 2: DelayWarrant (Недопустимая задержка D)
              ├──> Критерий 3: QueueWarrant (Статистическая очередь P95)
              └──> Критерий 4: SaturationWarrant (Степень насыщения X = v/c)
```

## 2. Реализованные стратегии критериев (`src/analysis/warrant_strategies.py`)

CARINA организует инженерный анализ на основе **паттерна «Стратегия» (Strategy Pattern)**, зарегистрированного в [`WarrantEvaluator`](../../src/analysis/warrant_evaluator.py):

### 2.1 Критерий 1: Критерий интенсивности движения (`VolumeWarrant`)
Оценивает объемы движения на подходах к перекрестку с использованием фундаментального уравнения транспортного потока:
$$q = k \times (v \times 3.6)$$
- **Пороговые значения Таблицы 4C-1 MUTCD:** Оцениваются количество полос на подходах и скоростной режим:
  - **1 полоса на главной / 1 полоса на второстепенной:** Условие A: $V_{главная} \ge 500\text{ авт/ч}$, $V_{второстепенная} \ge 150\text{ авт/ч}$. Условие B: $V_{главная} \ge 750\text{ авт/ч}$, $V_{второстепенная} \ge 75\text{ авт/ч}$.
  - **2+ полосы на главной / 2+ полосы на второстепенной:** Условие A: $V_{главная} \ge 600\text{ авт/ч}$, $V_{второстепенная} \ge 200\text{ авт/ч}$. Условие B: $V_{главная} \ge 900\text{ авт/ч}$, $V_{второстепенная} \ge 100\text{ авт/ч}$.
- **Коэффициент 70% для высокоскоростных магистралей:** Если разрешенная скорость на главной улице превышает $70\text{ км/ч}$ ($19.44\text{ м/с}$), все пороговые объемы масштабируются с коэффициентом $0.70$ (например, $500 \to 350\text{ авт/ч}$, $150 \to 105\text{ авт/ч}$).

### 2.2 Критерий 2: Критерий задержки движения (`DelayWarrant`)
Количественно оценивает эксплуатационную задержку на второстепенных направлениях по сравнению со временем движения в свободном потоке:
$$D = \frac{L}{v_{\text{факт}}} - \frac{L}{v_{\text{лимит}}}$$
- Проверяет превышение средней задержки над критическим порогом:
$$D_{ср} > D_{\text{порог}}$$
- Порог по умолчанию: `unacceptable_delay = 90.0 s`.

### 2.3 Критерий 3: Критерий 95-го процентиля очереди (`QueueWarrant`)
Аудирует накопление очередей с использованием статистического распределения 95-го процентиля для предотвращения переполнения полос (spillback):
- Рассчитывает эмпирическую длину очереди 95-го процентиля $P95(Q)$ по накопленным выборкам с датчиков.
- Критерий считается выполненным, если:
$$P95(Q) > Q_{\text{порог}}$$
- Порог по умолчанию: `max_queue_p95 = 15` автомобилей.

### 2.4 Критерий 4: Критерий коэффициента загрузки / степени насыщения (`SaturationWarrant`)
Оценивает отношение интенсивности движения к пропускной способности ($v/c$) по всем полосам подхода:
$$X = \frac{q}{N \times f_{\text{идеал}}}$$
Где:
- $q$: Пространственно-средняя интенсивность потока ($\text{авт/ч}$).
- $N$: Число полос на подходе.
- $f_{\text{идеал}}$: Идеальный поток насыщения на одну полосу ($1800\text{ авт/ч/полоса}$).
- Критерий выполняется, если максимальный коэффициент загрузки превышает критический порог:
$$X_{\max} > X_{\text{критич}}$$
- Порог по умолчанию: `saturation_critical = 0.85` ($85\%$ пропускной способности).

## 3. Математические модули (`warrant_math.py`)

Расположены в [`src/analysis/warrant_math.py`](../../src/analysis/warrant_math.py):
- **`compute_volume_q(density, speed)`:** Вычисляет пространственно-среднюю интенсивность потока $q = k \times (v \times 3.6)$.
- **`compute_delay(length, v_real, v_limit)`:** Вычисляет фактическую задержку транспортных средств относительно нормативной скорости.
- **`compute_p95(values)`:** Вычисляет эмпирический 95-й процентиль длины очереди.
- **`compute_saturation_ratio(volume, num_lanes, ideal_flow)`:** Рассчитывает степень насыщения ($X = v/c$).
